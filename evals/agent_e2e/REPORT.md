## 발견 1. 질문 절반이 추천 0개로 끝난다

50문항이 `모든 필수 조건을 충족한다고 확인된 후보가 없습니다` 경고와 함께 빈 목록을 냈다.
경고를 내는 동작 자체는 옳다(계약대로다). 문제는 빈도이고, 원인은 두 겹이다.

### 1-1. 후보가 한국 스토어에서 팔지 않는 고전 게임이다

`"게임 1개만 추천해줘"`를 따로 실행해 제외된 후보의 판정을 들여다봤다.

```
후보 30개 → 판정한 5개가 전부 탈락
  Max Payne                  : 가격 unmet (한국 스토어 미판매)
  X-COM: UFO Defense         : 가격 unmet (한국 스토어 미판매)
  X-COM: Terror From the Deep: 가격 unmet (한국 스토어 미판매)
```

`"3만 원 이하"` 쪽도 같다. 제외 16건의 가격 판정이 `unknown` 11건(원화 가격 확인 불가),
`unmet` 5건(미판매)이다. 후보로 올라온 이름이 Thief(1998), Baldur's Gate(1998),
Jagged Alliance(1995), Max Payne(2001)처럼 1990~2000년대 작품에 쏠려 있다.

즉 **IGDB 검색이 내놓는 후보 자체가 한국 Steam에서 구매 가능한 게임이 아니다.** 조건이 느슨한
질문(`count` 계열은 개수만 말한다)일수록 이 쏠림이 심해, `count` 80%·`tight` 100%가 빈 추천으로
끝났다. 반대로 `budget` 계열은 20문항 전부 추천을 냈는데, 예산이라는 조건이 붙으면서 후보 구성이
달라진 것으로 보인다. 검색 인자를 무엇으로 정렬·필터하는지는 이 평가셋의 범위를 넘고,
IGDB 담당 모듈(`app/tools/game_search.py`, `app/clients/igdb.py`)에서 볼 문제다.

### 1-2. 에이전트가 후보를 일부만 판정하고 포기한다

빈 추천 50건의 **제외 후보 수**를 세면 이렇다. `excluded_ids`는 "조회했는데 조건에 걸린 후보"이고
조회하지 않은 후보는 세지 않으므로(`app/agent/context.py`), 이 수가 실제로 판정한 후보 수다.

| 판정한 후보 수 | 문항 수 |
| --- | --- |
| 30개 (전부) | 16 |
| 17개 | 3 |
| 9~24개 | 7 |
| 5개 | 8 |
| 1~4개 | 11 |
| **0개** | **5** |

**빈 추천 50건 중 34건은 후보 30개 중 일부만 판정하고 포기했다.** 5건은 아무것도 조회하지 않고
"조건에 맞는 게임이 없다"고 답했다. 도구 호출 횟수를 보면 빈 추천 50건 중 45건이 `도구 호출 3회`다.
`search_games` 한 번, `get_prices`·`assess_hardware` 한 번씩 부르고 끝냈다는 뜻이다.
남은 후보로 두 번째 판정을 돌린 경우가 거의 없다.

러너의 안전망(`_ensure_checks`)은 **에이전트가 추천하기로 정한 게임**의 미조회 항목만 채운다.
후보를 더 보게 만들지는 않는다. 그래서 처음 고른 표본이 전멸하면 그대로 빈 목록이 된다.

같은 질문 `"게임 1개만 추천해줘"`가 평가 실행(E031)에서는 0개, 따로 실행했을 때는 1개를 냈다.
어느 후보를 표본으로 고르느냐에 결과가 달려 있다.

## 발견 2. 답변 문단이 추천 목록과 어긋난다 — 19문항

`answer_format` 실패 50건의 내역은 문장 수 31건, **게임 이름 누락 19건**이다. 뒤쪽이 실제 결함이다.

스모크 실행에서 처음 잡힌 형태가 전형적이다.

```
추천 목록: Thief II: The Metal Age, Thief: Deadly Shadows, Thief,
          Jagged Alliance, Jagged Alliance 2
답변 문단: ... 'Jagged Alliance'는 저렴한 4,090원에 구매할 수 있으며,
          'Jagged Alliance: Deadly Games'는 같은 가격입니다.
```

추천 목록에 있는 `Jagged Alliance 2`가 답변에 없고, 목록에 없는
`Jagged Alliance: Deadly Games`가 답변에 등장한다. 사용자는 카드에서 `Jagged Alliance 2`를
보면서 본문에서는 다른 게임 이름을 읽는다. 이름이 비슷한 시리즈물에서 잘 나타난다.

LLM 심판이 이 문항에 `grounded=3`을 주고 사유로 정확히 같은 지적을 했다. 코드 검사와 심판이
독립적으로 같은 결함을 가리켰다. 심판의 `grounded` 4점 미만 19문항은 게임 이름 누락 19건과
문항 수가 같다.

## 발견 3. 제외 조건이 검색에 전달되지 않는다 — E058

```
질문: 공포 빼고 3만 원 이하 게임 알려줘
추천: Vampire: The Masquerade - Bloodlines, Vampire: The Masquerade - Redemption,
      BioShock, Dungeon Keeper 2, Dead Space 2
```

추천된 5개 전부의 IGDB 장르·테마에 `Horror`가 있다. 제외 요청이 추천에 전혀 반영되지 않았다.

파서는 `excluded_genres`를 뽑지만, 그 값을 `search_games` 인자로 넘기는 것은 **에이전트의 판단**
이다(`app/agent/tools/search.py`의 `SearchGamesArgs.excluded_genres`). 러너의 후검증은 가격·사양만
보고 제외 장르는 보지 않으므로, 에이전트가 빠뜨리면 걸러지지 않는다. `exclude` 계열 15문항 중
추천을 낸 4문항에서 1건이 이 형태다.

## 발견 4. 사양을 말했는데 판정을 건너뛴 게임이 추천된다 — E081

루트 README의 예상 질문(하드웨어)이다.

```
질문: 내 노트북이 i5-1240P, RAM 16GB, 내장그래픽인데 원활하게 할 수 있는 게임 중에서
      평점 좋은 게임 추천해줘.
추천: Thief II: The Metal Age (사양 판정 skipped)
      Vampire: The Masquerade - Redemption (사양 판정 skipped)
```

사용자가 CPU·RAM·그래픽을 말했는데 사양 판정이 `skipped`다. `skipped`는 판정을 하지 않았다는
뜻이고, 러너의 후검증은 `met`과 `skipped`를 모두 통과로 본다. 그래서 "원활하게 할 수 있는"이라는
요청에 사양을 확인하지 않은 게임이 올라간다.

이 질문은 `evals/parser_conditions/`의 Q181과 같은 질문이고, 거기서는 파서가
`hardware.gpu="내장그래픽"`을 넣는 것이 문제였다. 두 평가셋이 같은 질문의 다른 층을 가리킨다.

## 발견 5. 빈 추천일 때 답변 길이 계약이 없다 — 29문항

`answer_format`의 문장 수 실패 31건 중 29건이 추천 0개인 문항이다. 추천이 있는 문항의 문장 수
분포는 `{3:14, 4:13, 5:9, 6:12, 2:2}`로 대체로 계약(3~6문장)을 지키는데, 빈 추천 쪽은
`{2:27, 3:20, 1:2, 4:1}`로 2문장에 몰린다.

`app/agent/schemas.py`의 `RecommendationDraft.answer` 설명은 조건 없이 "한국어 3~6문장"을
요구한다. 추천할 게임이 없을 때 3문장을 채우라는 것이 타당한지는 계약이 답하지 않는다.
**이 29건은 에이전트의 결함이라기보다 계약의 공백이다.** 빈 결과의 답변 길이를 따로 정하면
채점기도 함께 고쳐야 한다.

추천이 있는데 2문장인 2건은 계약 위반이다.

## 단계 실패 2건

`trajectory` 실패 2건(E047, E085)은 `가격`·`하드웨어` 단계가 `failed`로 끝난 경우다. 외부 API
호출 실패로 보이고, 두 문항 모두 추천은 냈다. 실패한 단계가 있었다는 사실이 최종 응답의
경고에는 드러나지 않는다.

## 실행 환경에 대한 기록

처음에 동시성 4로 돌렸을 때 **100건 중 50건이 연결 오류**로 끝났다. 45건이 질문 분해 단계의
OpenAI 연결 오류, 5건이 에이전트 루프의 연결 오류였고 LangSmith 전송도 DNS 해석에 실패했다.
한 질문이 IGDB·Steam·CheapShark·환율·OpenAI를 여러 번 부르므로 동시성 4는 로컬 네트워크에
과했다. 동시성 2로 낮춰 다시 돌린 것이 이 보고서의 실측이고 오류 0건이다.

이 경험에 따라 채점기는 **오류로 끝난 문항을 정확도 분모에서 뺀다**(`evals/price_hardware`와 같은
관례). 실행 환경 문제가 에이전트 품질 수치로 섞이지 않게 하려는 것이다.

## 읽을 때 주의

- **한 번의 측정이다.** 에이전트의 Tool 선택은 LLM이 하고 IGDB·Steam 데이터는 시간에 따라
  바뀐다. 같은 질문이 실행마다 다른 게임을 내는 것은 정상이다. 발견 1-2에 적었듯 같은 질문이
  0개와 1개를 오갔다.
- 회귀 비교는 축별 통과 수와 위반 유형으로 한다. 추천 목록을 직접 비교하지 않는다.
- `constraints` 98/100은 빈 추천 50건이 끌어올린 수치다. 추천을 낸 50문항만 보면 48/50이다.
- LLM 심판 점수는 사람이 공인한 정답이 아니다. 자동 정확도에 섞지 않았다.
- 발견 1-1(후보 쏠림)은 이 평가셋이 원인을 규명할 수 있는 범위를 넘는다. IGDB 검색 인자와
  정렬을 보는 별도 평가가 필요하다.
- 모델 alias의 서버측 버전을 고정하지 않았다.
