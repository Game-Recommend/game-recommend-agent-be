# 가격·하드웨어 최초 실측 결과

2026-09-14 14:26 KST 시작, `.env`의 `gpt-4o-mini`를 기존 `OpenAISpecJudge`로 호출했다.
가격·RAM 규칙은 준비한 사례를 모두 통과했지만, LLM은 정보가 부족할 때 판정을 단정하는 문제가 확인됐다.
실행 과정에서 제품 코드와 프롬프트, 기대 라벨을 수정하지 않았다.

한 질문(H30)에 후보 3개가 있어 LLM 판정은 64건이다. 자연어 질문은 설명용이며
현재 판정기의 실제 계약인 정규화 사양을 입력했다. 질문 이해 능력이나 전체 추천 품질 점수는 아니다.

라벨은 실행 전에 에이전트가 작성했으며 전문가가 검수한 성능 정답셋은 아니다.
별도 판정기나 동일 모델로 정답을 생성하지 않았다.

위 표는 1회차 원문을 수동 검토한 사례다. 상태 불일치는 2회차에도 동일했다.
문장 정확성을 전수 자동 채점한 점수는 아니다. API가 반환한 판정 객체는 `raw_verdicts`에 보존했다.
원본 HTTP/Responses 전체 응답이나 토큰 사용량은 보존하지 않았다.

## 다음 개선 우선순위

1. 사용자 항목과 요구 항목의 교집합을 먼저 확인하고, 비교 항목 없음·모호한 모델을 `unknown`으로 처리한다.
2. CPU/GPU별 상태와 사용한 사용자/최소 사양을 구조화해 반환하게 하고, 전체 상태를 코드로 합성한다.
3. `unmet`인데 “이상입니다”라고 설명하거나 CPU와 GPU를 비교하는 근거 오류를 차단한다.
4. 변경 뒤 같은 고정셋으로 비교하고, 새로운 비공개 사례와 독립 벤치마크 검토 라벨을 추가한다.

현재 작업은 검증이므로 제품 로직과 프롬프트를 개선하지 않았다.

# v2 개선 결과 (2026-09-14, 판정기 구조 변경 후)

baseline의 개선 우선순위 1~3을 반영하고 같은 50문항을 2회씩 재실행했다 (`runs/v5`, 중간 시도는 `runs/v2`~`v4`).
모델은 그대로 `gpt-4o-mini`다.

## 바꾼 것

| 구분 | 변경 | 해결한 실패 |
|---|---|---|
| 프롬프트 | reason 예시 문장 삭제 | 예시의 "RTX 3060"을 사용자 부품처럼 베끼던 H07~H09 |
| 프롬프트 | 미확인 부품·VRAM 미명시·세대 차이 규칙 추가 | 실제 게임에서 RTX 3060을 VRAM 미달로 오판, i5-1240P를 i5-8400 미달로 오판 |
| 출력 구조 | LLM은 부품별 `{component, status, note}`만 내고, 전체 판정·이유 문장은 코드가 합성 | GPU만 보고 통과(H15), 미달인데 "이상입니다"(H27), CPU/GPU 혼합 설명 |
| 코드 | 사용자·게임 양쪽에 값이 있는 항목만 `compare`로 지정. 공통 항목 없으면 LLM 없이 `unknown` | H17, H18 |
| 코드 | 사용자 부품에 3자리 이상 모델 번호(또는 Iris/UHD 등 내장 계열명)와 알려진 제품 계열이 없으면 LLM 없이 `skipped` "모델 확인 필요" | H08~H12, H15, H16 |
| 코드 | Apple Silicon은 `skipped` "Mac 사양 판정 미지원" (Steam `pc_requirements`는 Windows 기준) | — |

## 라벨 변경 (팀 방침)

모델명 없는 사용자 부품(H08 `i5`, H09 `GeForce`, H10 `내장그래픽`, H15, H16)과 알려진 계열이 아닌 부품(H11, H12)은
`unknown`(제외) 대신 **`skipped`(통과 + 최소·권장 사양 표시 + 되묻기)**로 처리하기로 했다. 이유:
"내장그래픽"만 말한 사용자에게 추천 0개를 주는 것보다 사양을 보여주고 판단을 맡기는 편이 낫고,
GPU를 무시하고 CPU만 비교하면 "미달인데 충족"이 생기므로 무시는 안 된다. 이 7개는 라벨을 `skipped`로 바꾸고 `expects_llm=false`로 두었다.

9개 중 7개(H08~H12·H15·H16)는 라벨을 바꾼 것이고, 나머지 둘(H17·H18)은 비교할 공통 항목이 없어 코드가 `unknown`으로 처리한다.

**원래 라벨 기준으로 읽으면** 위 7개는 `unknown` 기대에 `skipped`가 나온 것이라 68/75 (90.7%)다. 두 수치의 차이는 정확도가 아니라 방침 차이다.

## 남은 한계

- 합성 요구 사양 기준이며 실제 Steam HTML 다양성은 별도 smoke(실제 5개 게임 × 3케이스)로만 확인했다.
- `unknown`을 유지하는 능력(H13, H14, H28, H30-3)은 8/8이지만 표본이 적다.
- 알려진 제품 계열 목록은 수동 관리다. 목록에 없는 실제 부품(예: Quadro 외 워크스테이션 제품)은 판정 대신 사양 표시로 빠진다.
- 이유 문장은 코드가 만들어 사실 오류는 없지만, `note`(LLM이 쓴 30자 근거)의 품질은 채점하지 않았다.
