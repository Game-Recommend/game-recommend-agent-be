## 재현되는 실패 4종

### 1. "친구 N명이서"를 N+1로 센다 — 6문항, 18/18 실행 실패

프롬프트 3절은 두 표현을 명시적으로 갈라 놓았다. `친구 네 명과`는 5, `친구 네 명이서`는 4다.
`이서` 쪽이 한 번도 맞지 않았다.

| 문항 | 질문 | 기대 | 실제 |
| --- | --- | --- | --- |
| Q060 | 친구 네 명이서 같이 할 게임 찾고 있어 | 4 | 5 |
| Q061 | 친구 세 명이서 할 게임 알려줘 | 3 | 4 |
| Q081 | 친구 세 명이서 온라인으로 할 게임 | 3 | 4 |
| Q083 | 친구 네 명이서 온라인으로 협동하는 게임 찾고 있어 | 4 | 5 |
| Q182 | (루트 README 예상 질문) 친구 4명이서 온라인으로 같이 할 게임… | 4 | 5 |
| Q188 | 친구 세 명이서 한 화면에서 할 무료 파티 게임만 알려줘 | 3 | 4 |

반면 `친구 N명과`(Q057–Q059, Q066)와 `둘이서`·`셋이서`(Q063, Q065)는 전부 맞았다.
즉 `친구` + `N명이서` 조합에서만 사용자를 한 명 더 센다.

영향: 4인 게임을 찾는 질문이 5인 조건으로 검색된다. Q182는 발표용 예상 질문이다.

### 2. 전용 필드가 있는 조건을 preferences에 중복한다 — 2문항

| 문항 | 질문 | 전용 필드 | 중복된 preferences |
| --- | --- | --- | --- |
| Q011 | 4만원 이하면 좋겠어 | `max_price_krw=40000` | `["4만원 이하 선호"]` |
| Q171 | 협동 게임 추천해줘 | `play_mode="cooperative"` | `["협동 선호"]` |

프롬프트 총칙이 금지한 중복이다. 더 볼 것은 **`conditions.py`의 안전망이 새는 지점**이다.
`_PRICE_CONSTRAINT_PATTERN`은 이 중복을 지우려고 있는 정규식인데, 패턴이 `이하|미만|이내|까지`
뒤에 `\s*$`를 요구한다. 뒤에 `선호`가 붙으면 `fullmatch`가 실패해 그대로 남는다.

```
'4만원 이하'       → 지운다
'4만원 이하 선호'   → 남긴다   ← 실측에서 나온 형태
'20000원 까지 선호' → 남긴다
```

영향: 같은 조건이 구조화 필드와 자유 문장에 두 번 들어가, 최종 답변 LLM이 같은 말을 반복할
재료를 받는다. `협동 선호`는 지우는 규칙 자체가 없다.

### 3. "내장그래픽"을 GPU 모델명으로 넣는다 — Q181, 루트 README 예상 질문

```
질문: 내 노트북이 i5-1240P, RAM 16GB, 내장그래픽인데 원활하게 할 수 있는 게임 중에서
      평점 좋은 게임 추천해줘.
실제: hardware.gpu = "내장그래픽"
      platforms   = ["노트북"]
```

프롬프트 1절은 `'good PC'`나 `'integrated graphics'`에서 CPU·GPU 모델을 만들지 말라고 하고,
`hardware.gpu must contain the GPU model name only`라고 못 박는다. 모델명을 **지어내지는**
않았지만 모델명이 아닌 문자열을 GPU 자리에 넣었다.

영향: `SpecJudge`(`app/clients/hardware_judge.py`)가 GPU로 `"내장그래픽"`을 받아 게임 요구
사양과 비교한다. 판정 근거가 실제 성능과 무관한 문자열 비교가 된다.

부수 관찰: `platforms`에 `"노트북"`이 원문 그대로 들어갔다. `conditions.py`의 validator는
`hardware.os`의 플랫폼 표현만 지우고 `platforms`는 손대지 않는다. IGDB 플랫폼 매칭이 `"PC"`를
기대한다면 이 값은 걸리지 않는다. 이 문항의 정답은 `platforms`를 주장하지 않아 실패로
집계되지 않았다.

### 4. 턴제 소프트 불호가 하드 필터로 승격된다 — Q183, 루트 README 예상 질문

```
질문: 지금 2만 원 이하로 살 수 있는 게임 중에서 스토리가 중요한 RPG 추천해줘.
      턴제 게임은 별로 안 좋아해.
기대: preferences에 "턴제 비선호"
실제: excluded_genres = ["Turn-based"], preferences = ["스토리가 중요한 게임 선호"]
```

프롬프트 2절은 `"턴제도 별로야"`를 예시로 들어 `"턴제 비선호"`를 `preferences`에 넣고 일반
카테고리를 만들지 말라고 한다. `conditions.py`의 validator에도 이 의도를 받는 코드가 있다 —
`preferences`에 정확히 `"턴제 비선호"`가 있으면 `excluded_genres`의 턴제 필터를 지운다.
그런데 파서가 `preferences`에 아무것도 남기지 않으므로 **validator가 발동하지 못하고**
`excluded_genres`의 턴제가 살아남는다.

영향: "별로 안 좋아해"라는 약한 불호가 턴제 RPG를 후보에서 전부 제외하는 하드 필터가 된다.
`preferences`는 최종 답변 LLM이 참고하는 약한 신호이고 `excluded_genres`는 검색 단계의 제외
조건이므로, 두 필드의 차이가 그대로 추천 결과의 차이가 된다. 발표용 예상 질문이다.

## 회차 사이에 갈린 문항 2개

| 문항 | 질문 | 통과 | 실패한 회차의 출력 |
| --- | --- | --- | --- |
| Q029 | 2만 원대로 살 만한 게임 | 2/3 | `max_price_krw=20000` |
| Q080 | 친구 두 명과 같이 할 게임 알려줘 | 1/3 | `play_mode="cooperative"` |

Q029는 프롬프트 4절의 "`3만 원대`를 정확한 상한으로 바꾸지 말라"를 3회 중 1회 어겼다.
Q080은 "친구와 함께한다는 말이 협동을 뜻하지 않는다"(3절)를 3회 중 2회 어겼다. `같이`를
협동으로 읽는다.

Q080의 방향으로 한 가지 더: Q060의 출력에는 정답이 주장하지 않은 `connection="local"`도
있었다. `같이`에서 로컬 플레이를 유추한 것으로 보인다. 프롬프트는 "한 화면·한 컴퓨터"를
로컬의 조건으로 든다.

## 단발 관찰

아래 두 문항은 3회 반복에서 재현되지 않았으나 기록해 둔다. 근거가 되는 1차 실행(정답 수정 전,
200문항 × 1회, 187/200)의 원시 기록은 [runs/20260917T063220Z](runs/20260917T063220Z)에 있다.

1. **원하는 카테고리가 `excluded_genres`로 반전** — 정답 수정 전 1차 실행(단일 회차)에서
   Q200 `"Ryzen 5 5600, RX 6600, RAM 16GB PC로 할 공포 게임 2개"`가
   `excluded_genres=["Horror"]`, `genres=[]`를 냈다. 사용자가 **원한** 카테고리를 제외 조건에
   넣은 것으로, 이 평가셋에서 가장 심각한 형태의 실패다. 3회 반복에서는 3회 모두 통과했다.
   빈도는 낮고 영향은 크므로 반복 횟수를 늘린 실행에서 다시 확인할 값이다.
2. **`hardware.os`에 플랫폼 표현** — 같은 1차 실행에서 Q107 `"구형 노트북으로 할 게임 알려줘"`가
   `hardware.os="구형 노트북"`을 냈다. `conditions.py`의 validator는 os가 정확히
   `pc`·`computer`·`컴퓨터`·`노트북`일 때만 지우므로 `"구형 노트북"`은 그물을 빠져나간다.
   채점기의 공통 불변식을 부분 일치로 넓혀 이후 실행에서 잡히게 했다.

## 평가셋 자체에 대한 정정

최초 실행에서 실패한 13건 중 2건은 파서가 아니라 **정답 라벨이 틀린** 경우였다. 고쳐서 다시
돌렸고, 위 수치는 고친 뒤의 것이다.

- `"대전 게임 추천해줘"`에 `play_mode="competitive"`를 기대했으나 파서는 `genres=["Fighting"]`을
  냈다. 한국어에서 "대전 게임"은 격투 장르를 뜻하는 것이 표준 독법이고, 프롬프트에 "대전"이
  competitive 트리거로 적혀 있지 않다. 계약이 보장하는 표현(`"서로 경쟁하면서 하는 게임"`)으로
  바꿨다. **프롬프트에 한국어 트리거 목록이 없다는 것 자체가 빈 구석이다.**
- `"턴제 빼고 RPG 추천해줘"`에 `preferences`의 턴제를 기대했으나 파서는
  `excluded_genres=["Turn-based"]`를 냈다. `빼고`는 하드 제외 표현이므로 타당하다. 프롬프트
  2절의 턴제 규칙은 `별로야` 같은 소프트 불호를 겨눈다. 하드 제외의 정답을 계약이 정하지
  않았으므로 이 문항은 카테고리 추출만 채점하게 바꿨다.

## 읽을 때 주의

- 이 수치는 **프롬프트 계약을 얼마나 지키는지**다. 계약이 옳은지는 별개 문제이고, 위 정정 2건과
  단발 관찰 2번은 계약이 정하지 않은 구간을 가리킨다.
- 3회 반복은 흔들림을 드러내기에 최소한이다. 단발 관찰 1번처럼 빈도가 낮은 실패는 3회로 잡히지
  않는다.
- 모델 alias `gpt-4o-mini`의 서버측 버전을 고정하지 않았다. 같은 데이터·프롬프트 SHA-256이라도
  모델이 바뀌면 수치가 달라진다.
- `preferences`의 자유 문장이 사람이 보기에 적절한지는 채점하지 않았다.
